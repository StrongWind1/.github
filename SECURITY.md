# Security Policy

This is the default security policy for every [StrongWind1](https://github.com/StrongWind1) repository that does not ship its own.

## Reporting a vulnerability

Please report security vulnerabilities privately. **Do not open a public issue for a security report.**

Use GitHub's private vulnerability reporting on the affected repository: open its **Security** tab and choose **Report a vulnerability**. This opens a private advisory visible only to the maintainers.

If private reporting is not available on that repository, email [hello@strongwind.dev](mailto:hello@strongwind.dev) instead.

Please include:

- The affected repository and version, release tag, or commit.
- A description of the vulnerability and its impact.
- Steps to reproduce (proof-of-concept, affected command, sample input).

You can expect an initial acknowledgement within a few days. Once the issue is confirmed and a fix is available, we will coordinate a disclosure timeline with you.

## Forks

Repositories marked as forks track an upstream project. Report vulnerabilities in upstream code to the upstream maintainers.

## Supported versions

Security fixes are applied to the latest released version, or to the default branch for projects without releases. Please upgrade to the most recent release before reporting.

## Scope and responsible use

These projects include security-research tooling intended for authorized testing only. Running it against systems or data you do not own or lack explicit written permission to assess may be illegal. Reports demonstrating misuse against third-party systems are out of scope.
